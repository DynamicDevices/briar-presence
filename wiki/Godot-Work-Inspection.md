# Work inspection in the uninstalled Godot candidate

[Wiki home](Home.md) · [Design](../design/inspection/0.1-proposal/DESIGN.md)

Alex accepted the inspection mock-up as the design direction on 11 November
2026 and asked Briar to implement it in the separate development candidate.
This does not constitute independent code review or actual desktop acceptance.

## Prepare and try

From `implementation/`, using the existing verified engine and dependencies:

```sh
node scripts/api-overlay-recording.mjs --inspection
node scripts/launch-godot.mjs --inspection
```

The first command generates an ignored, local synthetic scene tape. The second
opens a separate candidate only when Alex chooses to run it. Neither command
installs/replaces the working overlay. Briar does not launch a visible window
while Alex is away. The ordinary study launcher and old API recording remain
available; the accepted light generator/Canvas renderer are unchanged.

The opt-in demo uses the mock-up's three tasks, two concerns and one response
request. Its 26-second loop uses real accepted API transitions: acknowledgement
at 6 seconds, explicit closure at 10 seconds, lease expiry at 22 seconds and
an unknown view at 22.5 seconds. One concern stays unresolved after the other
is closed. These are synthetic demonstration policies, not API defaults.

## Interaction

Click the face, or use Enter/Space while it has keyboard focus, to open the
pale, rounded inspection panel beside it. Nothing opens on a concern's arrival.
The face keeps its existing renderer, native drag/resize paths and stay-above
setting. Moving at least six pixels turns a face press into a drag, consuming
the click. Corner resize takes priority. There is no permanent resize widget.

Task buttons reveal impact, evidence, uncertainty, freshness and response details.
Selection is local to inspection; it cannot set shared focus. Quiet/finished
tasks remain inspectable. Orphaned concerns/requests are listed explicitly.
The panel has no fake acknowledgement or resolution buttons: this first version
is read-only. It displays the accepted state, including “acknowledged — still
open”, explicit resolution and “source unavailable — status unknown”.

Escape or Close hides the panel and requests focus back to the face. All work
clears only local selection. Display settings opens the existing separate
settings window. The panel is borderless and non-modal, with scrollable content,
non-colour labels and visible keyboard focus. It follows the face and applies
display-relative text sizing without pausing the face's animation loop.

Placement tries right, left, below and above without covering the face. If the
screen/face geometry leaves no usable panel space, it refuses overlap, logs
`inspection-no-space` and leaves the face unchanged. Alex may need to move or
shrink an unusually large face; this is a known limitation, not verified native
small-screen usability. Actual cross-display placement still needs desktop tests.

## Finite checks and limits

```sh
node scripts/test-inspection-godot.mjs
node scripts/test-inspection-godot.mjs --full
```

This generates accepted-state vectors and a small scene tape, verifies the
pinned engine, compiles the study and test, and runs headlessly with finite
process deadlines. Vectors compare native projection with the browser design's
model, including simultaneous producers with matching task IDs and omitted or
unassigned facts. Programmatic widget/input checks cover local selection,
unknown labels, keyboard close/open, click-versus-drag and corner priority.
Results and exact source hashes are recorded in
`implementation/test-artifacts/godot-inspection-results.json` and its log.
The `--full` check uses the full tape generated by the first preparation command;
the default uses a small generated tape. The package source inventory includes
the host's new preload dependencies, with a regression check for missing files;
this is not evidence that a new standalone bundle was built or installed.

Headless checks are not rendered-pixel equivalence, native pointer/compositor
testing, screen-reader usability, independent code review or installed acceptance.
The full tape is the existing bulky fidelity-test format, not an MQTT payload,
production view protocol or LVGL implementation. No real tasks, transcripts,
broker connection, firmware or live harness are used.

Local candidate evidence: 94 Node tests passed with zero fail/skip/cancel; the
verified Godot engine passed 353 checks over 36 projection vectors and the full
inspection tape. The existing baseline tape retained its 20 passing headless
checks. Exact source hashes and logs are local artifacts; genuine CI and review
status are recorded on the development PR, not inferred from these local results.

## Native review finding: collapsed footer

Alex's desktop screenshot exposed footer buttons collapsing into narrow vertical
strips, leaving too little room for the tasks. The old tests created widgets but
did not check their settled layout. Alex explicitly approved the targeted layout
fix and restart of the separate candidate.

The footer now uses non-wrapping captions in a flow container; task rows expand
to the available width. On narrow panels the footer can use another row, while
tasks remain scrollable. Actual-layout regressions cover four scales, including
the trial display scale, caption widths, compact heights and task access. They
reproduce the original defect before the correction. The candidate was restarted
with the fix, but Alex's visual re-check is still pending. Passing these geometry
checks is not native readability, pointer or accessibility acceptance.
